# Widget Unified Protocol V1

日期：2026-10-31。状态：已确认的架构与协议约束；尚未实现。本文中的方法名和字段示例是待契约实现冻结的设计，不是当前可调用 API。

本协议统一内部和外部 Widget。内部 Widget 只是通过工厂预置清单安装、配置和授权的 Widget，不得保留绕过协议的业务路径。本文取代原 `widget-protocol-v2.md` 外部卡片规划；现有内部 `protocolVersion: 1` 不等于本协议已实现。

## 第一部分：协议

### 1. 范围与基本约束

- 同一个 Joe、同一个 Widget 唯一，自动绑定唯一业务数据空间；用户无需选择空间。
- Widget 通过通信协议使用存储、动作、网络、行为记录和协作能力。Bridge 是该协议的宿主实现，不是另一套协议。
- Widget 不直接读取其他 Widget 的空间；通过 Joe 请求并调用对方显式开放的能力。
- 首期仅 Web、一个活跃客户端。不设计多窗口路由、客户端仲裁或多端同时写入。
- 不使用 iframe 承载 Widget。不加载第三方任意前端 JavaScript、HTML、CSS、表达式或可执行脚本。UI 使用受控宿主组件目录、声明式组合、数据绑定与有限交互规则，详见 [UI 协议](./widget-unified-protocol-v1-ui.md)。
- 复杂业务由协议调用 Provider；网络请求由 backend 受控执行。
- iOS / Android 未来作为客户端连接局域网、自部署或云端 backend，不运行完整 backend；沿用本协议，不要求与 Web 采用同一渲染技术。
- 物理存储位置属于 Joe 能力，不进入 Widget API。未来客户端和 backend 迁移保持逻辑数据身份。
- 首期不访问设备文件夹、照片、通讯录或其他应用数据；只开放 Widget 自身业务数据。

### 2. 身份、唯一性与生命周期

| 身份 | 语义 |
| --- | --- |
| joeId | Joe 的稳定身份，不由设备、会话或 backend URL 派生 |
| widgetId | 发布者命名空间下的稳定扩展身份，更新版本不变 |
| spaceId | Joe 自动创建的业务空间身份，删除重建后变化 |
| runtimeSessionId | 一次挂载的运行上下文，用于撤权、取消和释放订阅，不用于多窗口选择 |
| operationId | 业务操作身份，重试沿用 |
| requestId | 一次通信请求身份，用于关联响应 |
| eventId / cursor | 分别用于去重和事件恢复，不能混用 |

`(joeId, widgetId)` 唯一绑定逻辑 Widget 和活动空间。画布位置、可见性属于展示引用，不形成第二个 Widget 或空间。历史 canvasId、instanceId 可作为展示引用保留。

应用生成的不透明 ID 使用安全 `nanoid()`，创建一次并复用；版本、游标使用专用顺序值。外部 ID 原样保存并隔离命名空间。ID 不是凭据。

| 操作 | 结果 |
| --- | --- |
| 首次添加 | 创建逻辑 Widget 与空间，自动绑定 |
| 更新版本 | 保留身份和空间，验证兼容性并执行获准迁移 |
| 隐藏、收起、关闭界面 | 保留 Widget、空间和业务数据 |
| 移除并保留数据 | 撤销运行访问，重新添加时绑定原空间 |
| 移除并删除数据 | 删除空间并撤权，重新添加创建新 spaceId |

删除是持久的生命周期操作：先标记空间删除并拒绝旧请求，关闭订阅、撤销授权，再清理数据和附件。独立保留同步所需删除标记；备份清理期限单独声明。旧会话不能把数据上传到重建后的新空间。

### 3. 声明与注册

Manifest 声明发布者、widgetId、扩展版本、协议主版本、必需能力、资源/记录 schema、动作、模板绑定、行为、权限、网络规则和配额请求。

首期只接受受限数据声明。JSON Schema 限制大小、嵌套、复杂度和引用；禁止远程 `$ref` 自动联网。记录集合与索引须提前注册。模板和业务动作不能通过字符串注入代码。

示意（不是可直接安装的完整 manifest）：

```json
{
  "widgetId": "example.video",
  "version": "1.0.0",
  "protocol": { "name": "widget-unified", "major": 1 },
  "view": { "kind": "registered", "template": "video@1" },
  "capabilities": ["video.search", "video.play"],
  "permissions": {
    "required": ["storage.read", "storage.create"],
    "optional": ["behavior.emit"]
  },
  "network": { "origins": ["https://api.example.com"] }
}
```

注册验证发布者与命名空间，固定清单/内容摘要和版本。签名证明来源和完整性，不证明安全。发现工具不等于允许执行：只注册清单与授权交集中的工具。

内部 Widget 使用同格式 manifest、同注册流程和同策略入口。预置权限由宿主安装策略明确记录，不通过 `builtin` 标识跳过检查。设置、费用等宿主能力可有更严格的受众限制。

### 4. 通信与 Bridge

```text
Widget 声明 / 宿主模板
  → Web Bridge：方法校验、运行上下文、生命周期
  → Joe Runtime：身份、权限、路由、事务
  → 虚拟存储 / Provider / 获准网络 / 其他 Widget 能力
```

公共消息采用 JSON-RPC 2.0 请求、响应和通知语义；初期不开放批量请求。方法位于 `joe.*` 命名空间。内部函数调用和 HTTP 适配遵守相同契约。

```json
{
  "jsonrpc": "2.0",
  "id": "request-id",
  "method": "joe.storage.records.update",
  "params": {
    "collection": "bookmarks",
    "recordId": "record-id",
    "expectedRevision": 4,
    "value": { "title": "稍后观看" },
    "operationId": "stable-operation-id"
  }
}
```

示例 ID 是占位符。JSON-RPC 错误使用标准数值 code 和安全 message，业务错误放 `error.data.reason`，例如 `PERMISSION_DENIED`、`REVISION_CONFLICT`、`SPACE_DELETED`、`QUOTA_EXCEEDED`、`TARGET_UNAVAILABLE`、`CURSOR_EXPIRED`、`OUTCOME_UNKNOWN`。

owner、joeId、widgetId、spaceId、原始调用者和授权范围由宿主可信上下文绑定，不能相信消息自行声明。Widget 请求不接受任意空间选择或物理路径。

| 方法族 | 能力 |
| --- | --- |
| joe.session.* | 握手、版本/能力协商、关闭 |
| joe.permissions.* | 查询授权、申请声明过的可选权限 |
| joe.storage.* | 记录、附件、事务、变更订阅 |
| joe.capabilities.* | 查询调用者获准发现的业务能力 |
| joe.actions.* | 调用、取消、查询动作结果 |
| joe.provider.* | 调用已注册 Provider 动作 |
| joe.network.* | 获准的 HTTP 请求 |
| joe.ui.* | 展示、隐藏、聚焦、尺寸请求 |
| joe.behaviors.* | 提交已注册且获准采集的领域事件 |

握手顺序：宿主创建上下文 → 协商协议/能力 → 绑定授权及空间 → 返回初始化结果 → 开放调用。初始化返回已授予能力、配额和 UI 环境，不返回底层凭据。主版本不兼容或必需能力缺失则拒绝；可选能力支持降级。

每次请求严格校验参数、载荷、并发和超时。写操作使用 operationId；同 ID 不同载荷拒绝。权限变化后逐次重新校验，握手不是永久授权。

请求断开不等于业务撤销。取消只能尽力终止未提交工作；已提交写入保持成功。响应丢失后按 operationId 查询结果。外部写入只有在 Provider 支持幂等/结果查询时才能安全重试，否则返回结果未知。

事件包含订阅 ID、eventId、cursor、资源版本与必要因果信息。初始快照和 cursor 必须一致；重复事件去重、旧版本忽略、过期 cursor 重取快照。权限撤销或空间删除立即停止后续投递。

### 5. 动作与跨 Widget 协作

动作定义输入/输出 schema、执行位置、副作用、所需权限、确认规则、超时、幂等和取消语义。客户端播放与服务端修改均通过统一动作入口。

```text
待授权 → 已接受 → 执行中 → 成功 / 失败 / 已取消 / 结果未知
```

渲染回执独立于业务成功。播放请求被接受不代表已播放；必须依据播放器真实反馈。后台任务和明确动作由运行时执行，不为经过 Joe 而额外调用 LLM。

跨 Widget 路径为 A → Bridge → Joe → Bridge/能力执行器 → B。A 请求例如 `tasks.create`，Joe 发现并路由获准能力，而非让 A 读取 B 的空间。

调用链保留原始请求者、因果 ID 和授权依据。分别检查 A 的调用/数据转交权限与 B 的接收/执行权限，输出按允许范围投影。限制跳数、并发和循环；不能用 Joe 的大权限绕过 A 的限制。

backend 能力可在目标 UI 未挂载时运行；客户端能力需要当前 Widget 就绪，否则返回不可用。首期不做跨窗口路由。Provider、Widget 返回内容均是不可信数据，不能升级为系统指令或权限。

### 6. 权限与网络

有效权限为发布资格、版本声明、安装授权、数据归属和宿主策略的交集。授权申请只是请求，由宿主界面确认并在 backend 保存；Widget 不能自授权限。

权限绑定 Joe、Widget、空间、操作与数据范围；运行上下文叠加有效期限制。高风险确认绑定参数摘要、对象和期限；参数变化重新确认。UI、Agent 和后台任务复用同一策略服务。

数据读取、修改、删除、行为采集、发送模型和外传分别控制。新增域名、权限或副作用的版本升级重新授权。开发模式的测试数据/凭据与正式安装隔离。

`provider.invoke` 提供已封装业务动作；`network.request` 提供更基础的 HTTP 能力，两者均不能绕过受控出站策略。

- backend 执行网络请求，校验 HTTPS、规范化 origin、端口、必要的路径/方法规则。
- 默认禁止 localhost、私网、链路本地、云元数据和非 HTTP 协议；宿主预配置连接单独授权，不能被第三方 manifest 继承。
- 检查 DNS 与实际连接地址，防止重绑定；每次重定向重新检查，跨源不带原凭据。
- 凭据由 Joe 注入，Widget 只持有连接引用；禁止任意敏感头覆盖。
- 限制频率、并发、超时、响应体与解压后大小；日志脱敏。
- 域名允许访问不等于允许任意 Joe 数据外传；请求数据来源也要授权。

浏览器侧图片、媒体和播放器属于宿主模板的展示资源策略，须单独声明/审核来源，不能通过任意 URL 绑定绕过网络能力。YouTube 嵌入播放器是媒体集成，不是用 iframe 承载 Widget；其自身网络行为是明确的供应商信任边界。

### 7. UI 与行为

UI 契约独立维护在 [Widget Unified Protocol V1：UI 协议](./widget-unified-protocol-v1-ui.md)，属于本统一协议，不另建传输或权限体系。以当前 YouTube Card 为参考，覆盖组件目录、声明式组合、数据源请求/响应、订阅更新、局部状态、动作及宿主媒体能力。

此前仅选择整张 `registered` 固定模板的范围扩展为组合已注册宿主组件；整张卡片模板可以复用声明式组合。有限条件、格式化和状态转移由协议明确列举，不支持任意表达式、原型访问、通用编程语言或脚本运行。

宿主控制布局、展开和可见性；新资源不会自动打开被隐藏的 Widget。UI 使用 RareUI、Tailwind、Motion 并尊重 reduced-motion。内置与第三方使用相同 UI 描述和数据/动作契约，不保留私有业务捷径。

模板逻辑通过 Bridge 读写业务数据和调用动作。第三方不能直接提交任意 React 组件；进程内 Bridge 不是任意 JS 的安全沙箱，隔离来自不执行第三方代码及服务端强制鉴权。

行为定义包含事件 schema、用途、版本、保留期限和读取/外传策略。维持视频已确认的测量口径；第三方不能默认继承无限期保留或已有观看采集授权。行为上报不构成可信用户确认或高风险操作授权。

### 8. 虚拟存储

```text
稳定 Joe 身份 → 唯一 Widget → 自动绑定 Space
                              ├─ 集合与业务记录
                              ├─ 文件对象
                              └─ 版本与变更日志
```

首期当前 backend 是权威写入节点，Web 不支持离线业务写入。离线可展示宿主管理的只读快照，不能显示为已保存。Widget 不感知数据库、目录、服务器或同步拓扑。

记录有稳定 ID、schemaVersion、revision 和 value；通过预定义集合、字段、索引查询。文件使用 objectId，支持受限上传、读取和删除，不暴露磁盘路径或通用凭据。

提供读取、新增、更新、删除、订阅及附件权限；按集合/类别授予。业务删除权限不包含删除整个空间。配额包括记录数、总字节数、单对象大小、查询复杂度、事务规模和请求频率。

写入过程：鉴权/空间状态 → 幂等 → schema/配额/预期版本 → 事务提交数据与变更日志 → 返回结果 → 通知订阅者。实例和资源需要一起变化时同一业务事务提交，不发布半完成状态。

记录 revision 用于并发检查，空间 cursor 用于恢复；不混用。单次事务仅覆盖当前空间内支持的操作，跨 Provider 不承诺原子事务。文件先暂存并校验，提交引用后才可见；清理未引用上传。

迁移使用版本化受限声明，不运行第三方迁移脚本。未来同步保留稳定 ID、操作身份、删除标记、schema 版本、快照和附件校验信息。首期不实现离线合并、CRDT、多 backend 并发写入或跨服务器实时复制。

### 9. 版本与安全边界

统一协议从 V1 开始；扩展包、模板、集合 schema、行为定义可独立演进，但遵守统一协商与授权规则，不成为内部/外部两套协议。

授权和数据访问在 backend 强制执行。当前本机 Host/Origin 守卫不是完整身份授权系统；面向局域网、自部署和云端之前必须建立认证及所有入口的统一保护。

未来 backend 需要处理明文业务与记忆时属于受信任节点；仅把数据地址改成远程不等于安全迁移。持久数据可迁移，短期会话、设备路径和环境凭据不能直接同步。

### 10. 市场与可信分发

关联方案见 [Widget Market V1](./widget-market-v1.md)：自定义市场网站通过 GitHub App 提供登录和指定仓库授权，网页触发开发者仓库 Actions 验证、构建及必选 CI 身份签名，GitHub 不可变 Releases 分发产物，官方 Catalog 管理发布资格、版本和撤回状态。

开发者签名是正式发布及安装的必要条件，市场和 Joe backend 分别独立验证。GitHub 登录、仓库授权、签名有效、市场审核和用户运行权限互不替代。更新继续绑定本协议的唯一 Widget 数据空间。

市场只负责开发指导、发布与分发，不托管用户 Joe 记忆或 Widget 业务数据。压缩格式、扩展名和签名封装形式仍待讨论，不因市场方案确定而冻结。
