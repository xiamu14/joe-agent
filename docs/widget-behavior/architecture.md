# 架构设计：卡片行为记录分层

[返回索引](./index.md) · [方案](./solution.md) · [协议](./protocol.md)

状态：首期视频观看记录实现；未来记忆整理与桌面工具协议迁移未实施。

## 职责分层

| 层 | 职责 | 禁止承担 |
| --- | --- | --- |
| 卡片定义 | 行为名称、载荷 schema、记录时机、允许字段、证据策略及版本 | 自建上传队列、持久日志、全局记忆写入 |
| 卡片实例绑定 | 绑定定义版本、实例策略及作用域；允许关闭或收紧采集 | 擅自放宽用户设置或公共安全限制 |
| Canvas／Widget 运行时 | 注入并校验用户、Canvas、实例、设备、发起来源和因果关系 | 猜测领域偏好或信任模型编造的身份 |
| 通用行为记录层 | 契约校验、字段过滤、去重、顺序、接收确认及投递恢复 | 按 weather/video 等类型写业务分支 |
| 业务状态与事实存储 | 权威状态、不可变事件、必要数据版本、查询和清理 | 将状态快照当作用户意图 |
| 未来记忆整理层 | 消费领域信号，处理证据、冲突、有效期，更新 Mastra | 重建 Memory 引擎；本期不启用 |

首期仅视频观看适配器作为协议生产者，不提供独立关闭记录功能（Q14）。Canvas 运行时负责上下文注入，不采集 Canvas 操作；展开和最小化不生成行为记录。通用架构可扩展，不等于启用其他卡片采集。

## 首期视频适配边界

Q2、Q13 已确定：只记录用户发起播放与播放时长，发起包含直接点击和明确委托 Agent，排除 Agent 自发播放，并关联视频 ID、总时长；Q14 排除独立关闭记录。不复制搜索词、搜索结果或列表证据。暂停、缓冲、结束等状态只服务于计时，不默认成为行为事件。Q3 已确认：实际播放时间与内容覆盖分别计量；完播率使用去重片段覆盖除以总时长。Q4 已确认每次观看独立保存，再按需汇总。

视频适配器以单调时钟累计播放时间，结合连续播放期间的内容进度维护合并区间；拖动跳跃不填充为已看内容，倍速不能按墙钟时间估计覆盖。观测中断不补算未知时间；总时长无效时比例为未知。内部采样不作为额外产品行为上报。

计时、内容进度和播放来源识别属于视频适配器；公共记录层不懂播放器状态。现有播放器只提供 playing 状态，不能据此证明每一次都是用户点击；实施时需区分可直接观察的点击与来源未知的播放器启动。

## 数据流

```text
卡片定义 → 实例化绑定策略
                   ↓
用户直接操作 → 卡片适配器 → 运行时上下文 → 校验／可靠记录 → 业务事实
Agent 工具调用 → Mastra → 客户端执行 ────────┘
后台资源更新 → 数据适配器 ──────────────────┘

业务事实 → 历史查询
业务事实 → [未来]领域证据提取 → 记忆整理 → Mastra Working Memory
```

客户端真实执行结果与 Mastra tool result 引用同一动作；工具消息、SSE 和行为日志不得被计为三次独立选择。

## 模块契约

- 定义注册入口接收受信任的卡片 manifest；外部 provider 必须经过独立注册和权限校验。
- 实例化创建绑定：definitionVersion、policyVersion、instanceId、canvasId 和有效记录策略。
- 记录入口接收已注册事件名称及领域 payload；公共字段由运行时补充，服务端重新校验归属。
- 不允许卡片直接提交全局偏好或执行任意记忆更新指令。
- 实例化时实际生效的策略必须可追溯；更新策略不重写历史含义。

Q13 的来源判定基于可追溯用户指令或直接交互；Agent 自发播放不创建用户观看记录。共同遵循 Q7、Q8 的真实播放门槛；不因委托路径增加重复观看或实现新的控制功能。

## 观看记录生命周期（Q4 已确认）

视频适配器在主动选择视频并发起播放时建立临时上下文；按 Q7，未成功播放不持久化点击或观看记录。确认成功播放后才将同一 watchSessionId 写入记录，暂停、最小化与恢复沿用。Q8 确认无额外最低时长门槛：获得正的可测实际播放时长即可持久化，单独 playing 回调不足以确认。切换视频、关闭卡片、离开或刷新页面结束；下一次主动观看生成新 ID。视频播放结束只停止计时，不擅自增加未经确认的新会话切分条件。Q9 确认同次观看只保存一次发起，暂停后继续或最小化后恢复不增加点击明细／计次。

观看记录固定视频、Canvas、实例归属，保存累计真实播放时长和内容覆盖区间。内部检查点更新沿用观看 ID 并递增版本；重试不再次累计同一批时长。接收端拒绝旧版本覆盖新值，同版本异值报冲突。

跨次汇总属于查询投影：实际时间求和，内容区间取并集；按相同 provider/videoId 与兼容视频时长解释。数据缺失或版本不可比时明确部分统计，不默认为完整历史。

浏览器离开时尽力结算但不承诺退出上报一定成功。异常终止保留最近检查点并标记完整性未知；关闭只结束并结算已有观看，不生成关闭事件或关闭记录。检查点间隔、持久队列与故障恢复属于后续实现细节。

Q10 确认中途出错保留已确认播放数据，不记录详细报错或累加故障期间时间；未关闭或切换视频时，恢复后沿用同次观看。

## 前后台播放边界（Q11 已确认）

切换到其他标签页或应用时，视频适配器必须请求真实播放器暂停，并同步冻结计时；仅关闭计时器不满足产品要求。前后台状态仅作为运行时控制信号，不持久化应用／标签页切换行为。

当前观看不因后台暂停结束；返回保持暂停并保留进度，用户确认已有修复（Q12 跳过）。避免现有展开、ready 等自动播放逻辑绕过后台暂停门控。计时与覆盖采样共享播放许可，禁止返回后用进度差补算后台内容。

网页适配需结合可见性与窗口焦点，区分 iframe 内控件焦点和真正切换应用；原生宿主未来可使用自身生命周期事件。定向检查已发现现有适配监听可见性／blur，检查 document.hasFocus，并约束前台播放；用户确认该问题已修复。本设计复用现有控制，不重复实施；本轮未运行其测试。暂停调用失败也不能继续记入后台时间，实施时验证播放器实际停止。

## 存储与一致性

复用现有 WidgetStore 的状态、版本与命令幂等。同步事件服务于 UI 恢复；行为事实服务于历史解释。二者通过因果 ID 关联，不把同步快照直接改称用户行为。

建议持久对象：版本化记录定义／策略、行为事件、按策略保存的数据证据，以及必要的待投递记录。是否新增物理表按实现阶段确定，不复制一套当前业务状态。

服务端状态变化与其事实记录应在同一事务提交，或通过同事务 outbox 可靠补交。不能业务成功后仅依赖一次尽力上报。

客户端本地行为使用可恢复队列；事件 ID 创建一次，接收确认后才移出队列。本期按观看 ID 合并待投递的累计检查点，保留最新版本，不自动过期。每 10 秒、网络恢复或存储更新时重试；页面退出尽力通过 keepalive 提交。不能声称浏览器存储在被清除后仍保证送达。

数据证据采用被允许的快照、差量或可解析版本引用。差量必须有基线；只有当前值、没有历史版本的资源不能仅存 revision 后声称可回放。

Q5、Q6 确认视频观看记录及其必要片段证据默认长期保留，不配置自动到期清理。首期不实现清除入口、删除 API、删除级联及防复活机制；原建议中的清除能力后置。

身份授权作用于事件、证据及查询。删除实例、隐藏卡片、删除观看历史是不同概念；现有关闭动作不删除观看数据。未来引入清除操作时，须同时设计证据清理、统计重算、离线补交和播放期间清除语义，但这些不属于本期交付。

## Mastra 边界

当前已经使用 Memory／LibSQLStore，固定 joe-local-user 是资源归属 ID，不是自定义记忆实现。

共享 Memory 服务，通过 resourceId 隔离用户、threadId 关联会话；创建新的 Memory 对象本身不构成数据隔离。Canvas 不自动等同于 Mastra resource，也不为每张卡片创建独立 Memory。

未来采用结构化 Working Memory 保存小而有效的偏好。定义 schema 和更新规则属于业务适配，持久化与记忆注入使用 Mastra。历史事件不全部塞入 Working Memory。

当前 LibSQL 原子合并能力需要运行时检查；未验证前不假设支持。未来写入应统一管理，避免多个写入者整份覆盖。当前单用户 ID 不更改；迁移身份时须同时处理现有会话与记忆归属。

桌面等待按既有审查评估 client tools 或 suspend/resume；没有在本设计中认定某一种已验证可替换。客户端仍承担真实执行，业务层仍承担结果校验和幂等。

## Canvas 与未来 workflow

- Canvas 使用稳定独立身份，不用会话 ID 替代。
- 事件记录发生时归属；移动事件同时携带原 Canvas 和目标 Canvas。
- 配置修改的发生位置与配置生效范围分开：在某 Canvas 修改全局设置，不表示设置只对该 Canvas 生效。
- 暂不创建 workflow ID、推断关系或偏好。未来显式关系可关联现有事实，不能伪造历史归属。

## 兼容与演进

新行为协议使用独立版本字段，不修改已有 widget protocolVersion、CanvasSnapshot.version 的语义。

已注册定义版本须保留解码能力；读取旧版本不要求执行旧卡片 UI。无法解释的版本明确拒绝或标记不可用，不静默当成最新 schema。

历史记录不能从缺少来源的旧同步事件回填为“用户主动操作”。迁移可标为来源未知；不人为补造时间、设备或意图。


## 实现映射

| 层 | 实际文件与责任 |
| --- | --- |
| 共享契约 | shared/widget-behavior.ts：信封、视频定义版本、时长字段、片段并集 |
| 视频定义 | backend/src/joe/video-behavior.ts：严格字段校验、累计值不回退、跨次汇总 |
| 通用持久化 | backend/src/joe/behavior-store.ts：注册定义查找、会话／画布／实例校验、事务内事件与最新投影 |
| 实例绑定 | workspace-preview.tsx 传入真实身份；behavior/recording.ts 统一组装上下文与事件 ID |
| 视频计量 | watch-measurement.ts / watch-recorder.ts / observe-watch.ts：采样、生命周期与检查点 |
| 通用投递 | behavior/delivery.ts：localStorage 待投递队列、接收确认、幂等重试 |

behavior_events 保留不可变检查点及服务端接收时间，behavior_records 保存每次观看最新投影；二者同事务提交。UI 同步日志仍由 WidgetStore 管理，未将同步重放当作行为。

保留 canvasId、instanceId 的前端投影仅用于上下文传递，后端仍检查会话映射和实例类型。本地单用户 owner 来自服务端现有身份，不接受客户端 owner。新接入多用户时仍需完善认证，不能将此本机校验当作多租户授权。
