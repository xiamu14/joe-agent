## 目标与当前范围

准确回答：谁，在什么 Canvas，对哪个卡片、哪版数据进行了什么操作，实际结果是什么。

当前建设范围仅为视频卡片的行为事实、必要数据证据，不包含关闭记录功能。Canvas 仅提供归属上下文，不采集布局、拖动、切换等操作；展开、最小化不记录。未来可据此找回历史、继续任务、分析 Canvas 使用模式，再将可靠偏好交由 Mastra Working Memory 保存。

当前不实施：新的 Agent 播放控制能力、桌面等待协议迁移、清除入口与清除 API、删除级联与防复活机制、行为兴趣推断、自动修改设置、workflow 识别与推荐、独立记忆数据库、逐次点击调用模型。

## 产品原则

- 当前状态、历史事实、阶段上下文、长期偏好具有不同用途。当前仅落实前两项。
- 全部卡片采用同一接入协议，不等于记录全部 DOM 事件或永久保存所有内容。
- 卡片负责定义领域语义；公共层提供归属、校验、幂等与投递。
- 用户主动行为、Agent 行为、自动刷新、恢复重放必须可区分。
- 保存成功才代表设置变化成立；收到命令不代表播放成功；超时不代表执行失败。
- 不把示例内容、外部结果或 Agent 自发动作解释为用户偏好。
- 不新增无关卡片功能；切换标签页／应用时暂停、保留进度、返回不自动续播已由现有播放器实现。本期只衔接计量。

## 现状依据

当前 WidgetStore 注册费用、设置、天气、视频四类卡片，保存实例、资源、命令和同步事件。该事件流未完整表达行为主体和意图。

视频最近播放、画布布局及布局模式目前保存在浏览器。对话已有 Mastra 消息历史；示例灵感、问答、待办不等同于真实用户实体。

现有领域词汇中的“卡片退场”不等于删除：行为命名必须区分收起、隐藏、切换退场和移除实例。

## 实施范围与顺序

1. 确认各卡片记录项、数据字段与保留边界。
2. 建立注册声明、公共信封、版本化证据与可靠记录路径。
3. 仅接入视频观看记录，验证真实来源和重试语义；关闭仅用于观看结算。
4. 桌面工具等待迁移保留为后续审查项：原生客户端契约未在此仓库确认，本期不替换 pending 回执，也不新增播放控制工具。
5. 验证记录与汇总的准确性；清除操作和偏好学习均后置。

## 验收方向

- 重试不重复记录，状态同步重放不生成新的用户行为。
- 相同类型卡片在不同 Canvas 的行为可独立定位。
- 卡片移动后旧记录仍指向原 Canvas；移除实例不冒充删除历史。
- 资源更新后仍能解释历史事件引用的必要数据。
- 新增卡片通过注册接入，不修改公共记录层的卡片分支。
- 记录失败不伪造成功或偏好；恢复路径能识别待补交数据。
- 切换标签页或应用时视频与计时同步暂停，不把后台经过的内容补入已播放片段；卡片内部播放器控件操作不误触发应用切换暂停。
- Q5、Q6 确认观看记录默认长期保留、不自动按天过期；首期不提供清除操作，不要求删除机制作为首期验收条件。

## 产品访谈记录

### Q1：首期覆盖哪些真实产品卡片？

问题：首期是否以费用、设置、天气、视频四类真实卡片，加 Canvas／卡片外壳操作为范围；对话只引用已有消息记录，灵感、问答、待办示例暂不采集？

建议：采用该范围。先将真实使用路径记录完整；对话避免双份正文，示例内容避免污染真实历史。

状态：已回答。用户决定仅记录视频 card widget；Canvas 不记录操作；卡片外壳只记录关闭，展开和最小化不计。对话沿用现有记忆。本记录取代问题中的四卡片建议。后续 Q14 明确没有关闭记录功能，关闭仅结算观看；当前范围以 Q14 为准。

代码核对：当前关闭按钮经 removeWidget 提交 visible=false，属于隐藏而非删除实例；scene.close 则退出展开状态，属于本期排除项。不能依据函数名 close/remove 判断采集语义。

对话说明：Mastra 消息历史保存对话；Working Memory 保存长期信息与偏好摘要，不等于完整对话记录。本次不新增对话采集。

### Q2：视频搜索结果保存整份列表，还是只保存用户选择的视频？

问题：搜索得到 10 个视频，用户只播放其中 1 个，是否保留该次搜索的全部结果摘要？

建议：保存搜索词和返回列表的必要元数据（视频 ID、标题、频道、返回顺序与获取时间），并关联后续选择；不保存视频文件、字幕或缩略图二进制。这样能找回未播放的结果，并知道用户当时有哪些选择。列表返回不代表实际曝光，更不代表用户喜欢。

状态：已回答。用户否决保存搜索结果和重复采集搜索词；仅需用户点击播放及播放时长，对比视频时长计算完播率。关闭记录后续由 Q14 排除。视频 ID 用于识别记录对象，总时长用于计算比例；不扩大内容元数据采集。

代码核对：当前播放器适配只暴露播放状态及控制方法，尚无总时长、进度或播放速率读取声明。已有最近播放不能代替时长记录。iframe 内原生控件点击也不能由现有 onStateChange 直接证明是用户点击，不能把所有进入 playing 的回调算成点击。

### Q3：完播率按实际播放时间占比，还是按不重复的已播放片段占比？

场景：10 分钟视频，用户把前 2 分钟播放 5 遍。累计播放时间是 10 分钟，但只看过 20% 的内容。倍速播放也会让真实用时与视频内容时长不同。

建议：实际播放时长单独累计（不含暂停、缓冲）；完播率使用不重复的已播放片段时长 ÷ 视频总时长，跳过内容不算、重复片段不重复加、倍速按实际覆盖内容计算。片段合并属于卡片内部计量，持久字段范围随本题答案确定。不具备可用总时长或观测数据时比例为未知，不伪造为零。

问题：是否采用这一口径？若选择仅用实际播放时间 ÷ 总时长，则文档明确它是播放时长占比，重复观看可超过 100%，不等同于内容完播率。

状态：已回答。用户采用建议：播放时长累计真实播放时间，排除暂停和缓冲；完播率按去重的已播放片段覆盖计算，跳过不算，重复不累加，倍速按覆盖内容计算。


### Q4：按每次观看保存记录，还是只保存每个视频的累计值？

问题：同一视频今天看 2 分钟、明天又看 3 分钟，是否分别保存两次观看记录，再按需汇总？

建议：分别保存。一次观看从用户主动选择视频并发起播放开始；暂停、最小化及恢复继续同一条，切换视频、关闭卡片或离开／刷新页面结束该条。返回后再次主动播放创建新记录。异常退出保留最后已确认数据并标明未完整结算，不能依赖退出回调保证最后一段送达。

每次记录保留 Canvas／实例归属、实际播放时长及合并后的播放片段；同一视频的累计完播率对这些片段再次取并集，不能把各次百分比相加。自动展开恢复播放不虚构新的用户点击。

状态：已回答。用户同意每次观看独立保存，暂停、最小化与恢复不拆分；切换视频、关闭卡片或离开页面结束，再次主动播放建立新记录。按需汇总实际播放时间，并以片段并集计算跨次完播率。

落地边界：watchSessionId 在一次观看开始时生成并复用，不等同于对话 sessionId。实例、Canvas、视频 ID 在该次记录中固定；该次更新按 revision 幂等接收，不能重复累加累计快照。按 Q7：点击发起但未成功播放不持久化点击或观看记录；待确认状态仅在客户端暂存，按 Q8 获得正的可测实际播放时长后持久化，不设额外门槛。页面异常退出保留已确认片段，终止原因与完整性分别表达，不伪造关闭操作。

### Q5：观看记录保留多久？

问题：每次观看的时长、片段和 Canvas 归属，是否默认保留到用户主动删除？

建议：默认长期保留，提供清除入口。当前只保存精简的观看事实，不保存搜索列表或媒体内容；长期保留便于找回观看历史和未来偏好分析。清除应同步影响累计时长和完播率，不能保留被删记录的派生统计。定期自动清理是另一选择，但会使累计数据仅代表保留期内观看。

状态：已回答。用户采用建议：观看记录默认长期保留，直到用户主动清除；提供清除入口，删除相关记录后同步删除或重算派生统计。长期保留不代表永不丢失或已有备份承诺。其他卡片不因此获得采集授权。

### Q6：清除记录提供哪些粒度？

问题：是否提供“删除某个视频的观看记录”和“清空全部观看记录”两个入口？

建议：首期提供这两种。单个视频按当前用户和 provider/videoId 清除其跨 Canvas 的全部观看记录；清空全部仅清除当前用户的视频观看记录。先不提供按日期、单次观看或 Canvas 筛选删除，也不删除对话、卡片实例或视频资源。播放期间删除需使旧记录停止续写，防止待上传检查点把记录恢复；是否立即继续生成新记录需后续明确。

状态：已回答。用户决定暂不实现清除操作。本决定覆盖 Q5 建议中“本期提供清除入口”的部分，长期保留不变。首期不实现删除 API、入口、级联重算或防复活机制；未来真正引入清除时再整体设计，不预先指定清除粒度。

### Q7：用户点击播放但最终未能播放，是否保留该次点击？

场景：用户选择某个视频，但嵌入受限或网络故障，实际播放时长为零。

建议：保留已直接观察到的点击，记录播放时长为零，并区分未开始、失败、未知；不能当作用户看过或不喜欢。总时长未知时完播率为空；总时长已知且确认未播放时完播率为零。不记录详细错误内容，仅保留必要状态。

状态：已回答。用户决定不保留未成功播放的点击或观看记录。此决定覆盖上面的保留建议；播放器等待期间不提前持久化零播放记录。已成功播放后发生错误，不抹去此前真实播放事实。按 Q14 不提供独立关闭记录，也不借结算保留失败点击详情。

### Q8：成功播放后，是否不设额外最低时长门槛？

问题：用户确实播放了 1 秒后切换视频，这次观看是否保留？

建议：保留；确认真实播放且获得正的可测播放时长后即可记录，不设 5 秒或 10 秒门槛。短观看也是事实，未来是否用于偏好判断另行决定；仅收到 playing 状态但无实际播放证据不算。

状态：已回答。用户采用建议：确认真实播放且获得正的可测播放时长后即可记录，不设额外 5 秒／10 秒门槛。仅收到 playing 状态但没有实际播放证据不保留。时长来自可观测数据，不声称识别用户注意力。

### Q9：同一次观看暂停后再次点击播放，是否单独计次？

问题：用户选中视频开始播放，随后暂停并恢复三次，是否只记录一次观看发起，恢复只累计时长和覆盖片段？

建议：只记录一次观看发起。暂停后继续、最小化后自动恢复不增加播放点击次数，也不拆分观看记录；切换视频或关闭后再次主动播放才创建新观看。首期不增加播放按钮点击明细或恢复次数字段。

状态：已回答。用户采用建议：同次观看只记录一次观看发起；暂停后继续、最小化后恢复只累计时间和覆盖片段，不保存重复点击明细或恢复次数。切换视频或关闭后再次主动播放创建新观看，遵守 Q4。

### Q10：观看途中出错，是否保留出错前的观看数据？

问题：视频已经正常播放 2 分钟，随后发生网络或播放器错误，是否保留已确认的 2 分钟和覆盖片段？

建议：保留。Q7 的“不保留”只针对从未成功播放的尝试；中途出错不撤销此前真实观看。只保存最后确认的数据，不补算故障期间时间，不采集详细报错内容。若未切换视频或关闭卡片，恢复后仍可续写同次观看。

状态：已回答。用户采用建议：中途出错保留已确认的播放时间与覆盖片段，故障期间不计时，不保存详细报错；未关闭卡片或切换视频时，恢复后续写同次观看。

### Q11：切到其他标签页后仍在播放，是否继续计时？

问题：用户切换到其他标签页或应用，视频仍在后台播放，是否继续累计实际播放时长及覆盖片段？

建议：继续计入可确认的播放，不用页面可见性猜测用户是否在观看或听音频。这些指标描述播放事实，不表示注意力。后台暂停或无法可靠观测的时间不补算，不用两次进度差直接填满中间缺口；不另行采集切换标签页或应用的行为。

状态：已回答。用户不采用后台继续播放计时的建议。切换到其他标签页或应用时，视频应自动暂停，计时同步暂停；不允许只停止统计而让视频继续后台播放。不生成独立切换页面／应用行为记录，暂停不结束当前观看。返回不自动续播，保留进度（Q12 用户确认已有修复）。

实现边界（Q12 校正）：用户确认已有修复。定向代码检查发现 mount-youtube-player.ts 已监听 visibilitychange／blur 并在后台暂停，use-youtube-player.ts 已约束前台播放；不重复改造、不把已有修复算作本设计交付。本期计时需跟随真实暂停，且不补算后台内容。未在本轮运行播放器测试。

### Q12：返回页面后，视频是否等待用户手动继续播放？

问题：切回视频所在标签页或应用后，是自动恢复播放，还是保持暂停直到用户点击播放？

建议：保持暂停，用户手动继续，避免返回即出声。恢复仍属于同次观看，不新增播放点击明细，遵守 Q4、Q9。

状态：跳过。用户明确已修复“切换标签页或应用时暂停视频，保留播放进度；返回页面后不自动续播”。作为现状约束，不再提出该问题或列为待实现产品功能。










### Q13：用户让 Agent 播放，是否与直接点击一样记录观看？

问题：用户说“播放这个视频”，Agent 执行后成功播放，是否同样建立观看记录？

建议：记录。用户直接点击和明确要求 Agent 播放都属于用户发起，分别标记 directInteraction 与 userInstruction；仍须真实播放后才保存。Agent 未经用户要求主动播放不作为用户观看记录来源。该规则只定义已有或未来播放能力的记录语义，不要求本期新增语音播放或 Agent 控制能力。

状态：已回答。用户采用建议：直接点击与明确要求 Agent 播放均纳入观看记录，并区分来源；Agent 自发播放不纳入。两类均遵循成功播放才保存、正的可测时长即可、同次恢复不重复计次的规则。不因此新增 Agent 播放能力。

### Q14：视频卡片关闭是否也只记录用户主动关闭？

问题：是否只记录用户点击关闭或明确要求 Agent 关闭，而不将刷新、离开页面、系统恢复或 Agent 自行隐藏记为用户关闭？

建议：采用。只有已确认卡片被隐藏才保存关闭事实；刷新或离开页面只结算观看，不能伪造关闭。即使本次没有成功播放，明确关闭仍可按 Q1 独立记录，不保存失败播放详情。

状态：已澄清。用户指出“没有关闭记录功能”。不采集或保存独立关闭事件，不新增关闭历史或关闭计数；本题建议不采用，并覆盖此前 Q1 对关闭采集的描述。关闭仍按 Q4 结束并结算已有观看记录；没有有效观看时不产生记录。



## 首期实现与验证

已实现：用户主动选播后，仅有实际进度才持久化；每次观看独立记录，播放时间与片段覆盖分开；断网暂存与重试；后端归属校验、版本校验、幂等及跨次汇总。没有新增 UI、关闭记录、搜索采集、清除入口或偏好推断。

使用现有本地单用户身份，保留当前 Mastra Memory 配置。Q13 的明确委托来源在类型和服务端可信入口保留，但当前仓库无 Agent 播放控制链路；浏览器不能自行声称 userInstruction，未实现的控制路径不算已交付。

每 250ms 采样，首次正的有效播放立即形成记录，之后每 5 秒及暂停／退出时提交累计检查点。该精度是近似测量，无法证明用户注意力；超过 1.5 秒的采样空洞、异常进度跳跃不补算。极短且无法观测的播放不伪造为已观看。
